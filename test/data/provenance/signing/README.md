# Experimental detached-signature interoperability fixture

`manifest.json` is a deliberately small byte string, not a complete archive
manifest. `envelope.json` contains ECDSA P-256/SHA-256 and pure ML-DSA-65
signatures generated by the Python reference implementation using OpenSSL
3.5.5. Rust verifies both signatures against the same bytes. Only public,
self-signed test certificates are included; the temporary private keys were
discarded. These certificates are not trusted roots or authorized identities.

`transcript.sha256` hashes the exact binary signing transcript.
`canonical-envelope.sha256` hashes the sorted-key, compact ASCII JSON envelope,
including both signatures. Both reference implementations assert these values.

The v1 transcript is the concatenation of:

1. The ASCII domain `mzPeak-signature-v1` followed by one zero byte.
2. A policy byte: `1` ECDSA, `2` PQC, or `3` both.
3. A big-endian unsigned 32-bit signer count (one or two).
4. For each signer, sorted by algorithm name: a big-endian unsigned 32-bit
   ASCII algorithm-name length; its bytes (`ecdsa-p256-sha256` or `ml-dsa-65`);
   and the 32-byte SHA-256 digest of its leaf certificate in DER.
5. A big-endian unsigned 64-bit manifest byte length, then the manifest bytes.

Every signature covers this same complete transcript. This binds the algorithm
labels, full signer set, leaf certificate identities and declared policy, so
removing the PQC signature or changing the policy invalidates the remaining
signature. Relying parties also supply an independent minimum algorithm policy.

ECDSA signatures use ASN.1 DER encoding. ML-DSA-65 signatures use the standardized
3309-byte pure-mode encoding, with an empty context (not HashML-DSA). The envelope
is an experimental mzPeak raw-signature profile and is **not CMS/RFC 9882**.
Intermediate certificates are untrusted path-building inputs; cryptographic
verification does not establish certificate trust, roles, revocation, coverage,
or a trusted signing time.
